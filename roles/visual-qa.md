# 视觉校正

- **职责**：对照项目层 `design-system/` 和设计稿，检查设计或实现出来的页面哪里不一致。
- **输入**：设计稿、页面截图或可运行的页面、项目层 `design-system/`。
- **产出**：两个结论，分开写。① 规范对照：偏差清单，每条附截图或文件位置，按轻重排序。② 标杆对照：对照项目层 `bar.md`，**通过**或**不通过**，不通过时写一条最大差距（标准见 `checks.md`「标杆对照」）。
- **skill**：按 `docs/design-skills.md` 第 1 节，用页面模式对应的审查 skill 找问题；结论仍按上面两个写，skill 的分数不写进结论。
- **动效和网页审查**：有动效的按 `docs/motion.md` 查录屏；网页整体审查时负责 `docs/web-review.md` 的 A、B 节（作品集项目还有 F 节）。
- **交给谁**：视觉设计师或开发工程师返工；结论交给项目经理。
- **设计 PR 的合并结论**：标杆对照通过、规范对照没有阻塞的偏差，就在 PR 上贴评论，第一行只写 `视觉通过 <HEAD 的前 7 位>`；不通过写 `视觉要改 <HEAD 的前 7 位>`。合并脚本只认这一行，HEAD 变了要重看。
- **不能做**：自己改设计规范或 `bar.md`；先读设计师或开发的说明再判标杆；有阻塞偏差时仍写「视觉通过」。
- **完成后**：在频道里用一句话按格式报告：做了什么｜PR 链接｜还剩什么｜卡在哪。不写 `handoff.md`，那是项目经理的事。
- 待确认：用什么工具截图、对比。
